# 开发说明

## 结构

```
启动助手.command      统一入口：校验/编译 Swift 界面 → 准备 Python 环境 → 打开 .app
build_native.sh       编译 Native/ShinyHunt.swift 为 Mac刷闪助手.app（arm64, macOS 14）
Native/ShinyHunt.swift  SwiftUI 界面 + 原生输入（键鼠事件、辅助功能把游戏切到前台）
native_bridge.py      界面 ↔ 引擎的 JSON 行管道；自动接管游戏、保持前台、状态快照
app.py                引擎：刷怪循环、闪光检查、逃跑、去医院、换频道、自动恢复
screen_state.py       画面识别：用真实截图裁下的模板判断"现在是什么画面"
pp_recovery.py        去医院路线（22 步）与 PP 计数
mac_backend.py        截图（ScreenCaptureKit）、OCR（Apple Vision）、窗口查询
notifications.py      喵提醒（只在闪光/验证码时）
snapshot_policy.py    快照与日志轮转
assets/               模板图：逃跑按钮、战斗菜单、换频道窗口、screens/ 下各类弹窗
sim/                  模拟器：假游戏 + 真实截图帧，驱动真实代码做验收
tools/                测试脚本与 macOS 框架替身（stubs）
design/               界面设计稿源文件
```

进程关系：`Mac刷闪助手.app`（Swift）启动 `native_bridge.py` 子进程，通过 stdin/stdout 交换 JSON 行。
Python 发 `{"type":"state"}` 快照、`log`、`nativeInput`（让 Swift 发键鼠）；Swift 发 `{"action":...}` 命令。
键鼠事件由已签名、已授权辅助功能的 Swift 应用发出，Python 只需要屏幕录制和输入监控（F8）权限。

## 一轮是怎么跑的（app.py `App.run`）

1. `attach_game`：找到 PokeMMO 里内容区 1024×768 的窗口，切到前台并定位（不需要预览）。
2. 启动画面若有弹窗先关掉；记录刷怪点参考图。
3. `ready` → 按 5（甜甜香气）→ `battle`：OCR 找逃跑按钮 → 两次独立截图的闪光检查 → 在逃跑按钮内随机点 → `return`：确认回到地图。
4. 每 6 轮 `recover_pp`（PP果刷闪）；到时间 `switch`（换频道）。
5. 任何游戏情况的 `RuntimeError` → `recoverable()` → `recover_from()`：看画面、做唯一安全的动作、再看，最多 10 步。

## 安全规则（改代码时不能破坏）

- **闪光、验证码、F8、手动停止永远不自动恢复**（`NO_RECOVERY`、`protection` 标志、`stop_event`）。
- 自动恢复遇到战斗**不自己逃跑**，交回主循环（主循环才有闪光检查）。
- 只有 `RuntimeError` 可恢复；程序错误（AttributeError 等）立即停。10 分钟内最多恢复 3 次。
- 永远不按 5 进一个被窗口挡住的画面（`blocking_ui`）。
- 通知只在闪光/验证码时远程发送；`notification.json` 不进版本库、不打包。

## 踩过的坑（别再踩）

- **PokeMMO 有多个窗口**，第一个未必是游戏画面；判断"游戏在前台"要看进程，不看窗口编号（21:49 实测）。
- 窗口标题里的 "РokеМMO" 含**西里尔字母**，不要用标题全等匹配。
- macOS 可能拒绝后台进程的激活请求 → 由 Swift 用辅助功能 `kAXFrontmost` 拉到前台（`activate` 操作）。
- **按住方向键和鼠标点击只在游戏在前台时有效**；后台只有单次按键有效。所以现在强制前台运行。
- 把焦点还给"之前的程序"可能跳到别的桌面（Space）→ 游戏不可见。现在不再还焦点，并会自动切回。
- Apple Vision 会把「更换频道」读成繁体「更換」「頻道」，偶尔整行漏读 → `cn_norm` 归一化 + 截图模板兜底 + 固定行位置兜底。
- 「成功逃脱」提示很短，慢 OCR 会漏掉；其他玩家会挡住地图参考图 → 连续 3 帧只有信息栏也算回到地图、水面占比判断刷怪点。
- 治疗后最后一下空格、确认冲浪的空格都可能没被游戏收到 → 都有检查和补按。
- 切频道后新频道的玩家会挡住参考图（见待办第 1 条）。

## 测试与验收

```sh
tools/run_tests.sh                    # 单元测试，用 tools/stubs 替代 macOS 框架，任何电脑都能跑
python3 sim/run_sim.py                # 回放模式：OCR 结果来自 sim/ocr_cache.json（在 Mac 上用真实 OCR 录的）
python3 sim/run_sim.py interruptions  # 只跑某个场景
SIM_OCR_DELAY=0.8 python3 sim/run_sim.py   # 模拟 Mac 上较慢的 OCR
```

在 Mac 上：双击 `sim/1-OCR录制.command`（新增截图帧后重新录 OCR），`sim/2-模拟验收.command`（用真实 Apple Vision 跑全部场景）。

模拟场景（`sim/run_sim.py` 里的 `SCENARIOS`）：正常 14 轮、治疗后空格漏按、没走到岸边、换频道、频道列表读不到字、
逃脱提示漏读、冲浪确认没按上、游戏被切到后台 4 次、弹出锦标赛窗口 / 是否提示 / 走偏到街上。
**每修一个真实故障，先在 `sim/fake_game.py` 加故障注入复现它（旧代码要失败），再修。**

新增画面：把真实截图放进 `sim/frames/`，需要识别的话裁一块放进 `assets/screens/` 并在 `screen_state.TEMPLATES` 登记，
用全部帧跑一遍分数确认能区分开。

## 发布

运行时文件（日志、截图、`settings.json`、`notification.json`、`.runtime-python`、`.build/`、`.app`）都不进 git。
新机器上第一次双击 `启动助手.command` 会建 Python 环境并编译界面。
