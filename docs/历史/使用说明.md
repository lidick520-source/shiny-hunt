# Mac 刷闪助手 2.0

## 打开

双击「Mac刷闪助手.app」，或双击「启动助手.command」。应用与 Python 文件须保留在同一文件夹内，不要单独移动 .app。此处提供的应用已为 Apple Silicon Mac 编译；截图/OCR 后台需要 Python 3.11+ 及 requirements.txt 中的依赖。首次启动器会在缺少依赖时安装。本机运行不调用 AI。

## 日常操作

1. 打开 PokeMMO，使用窗口模式，游戏内容区设为 1024×768；甜甜香气绑定 5，瞬移绑定 4。
2. 打开「游戏预览」，检查系统权限。点击「5 秒后获取预览」并在倒计时内切回游戏。
3. 回到助手检查画面，勾选“画面完整，没有标题栏或裁切”。移动、缩放或关闭游戏窗口后须重新预览。
4. 首次保持「监测」模式，点「开始任务」。程序会切回游戏、进行 OCR 预热并触发遇怪，检查后停止。验证后可切换「自动逃跑」。
5. 随时按 F8（部分键盘为 Fn+F8），或点击窗口顶部「停止任务」。关闭助手也会停止输入。切回助手会导致游戏失焦，现有保护会停止任务。

## 四个页面

- 控制台：当前状态、最近停止原因、运行时间、完成遭遇、PP 使用轮数、恢复步骤、频道和休息倒计时、监测/自动逃跑切换。
- 游戏预览：截图确认和权限检查。界面启动后不会自动控制游戏。
- 设置：PP 自动恢复、换频道、喵提醒、计时重置和手动补满 PP 后重置。
- 运行日志：关键词搜索、跟随最新、日志文件及诊断截图入口。窗口只保留最近800条显示，磁盘日志沿用原轮转策略。

运行中锁定设置；先停止再修改。

## PP 恢复

每成功逃跑并确认回到地图后计一轮；“PP 使用”显示已完成的遭遇轮数，不是读取游戏实际 PP。累计六轮后，开启恢复则执行 4 瞬移、护士空格三次、S→D→W→D 返回、空格冲浪；未开启则停止。固定路线仍属实验功能，默认关闭。

恢复进度显示完成步骤和当前动作；停止后可在本次会话继续。中断的动作可能重新执行（尤其方向键按住中途停止），请先核对位置。退出应用后断点不保留；再次启动前人工确认位置和 PP。手动恢复完成并返回起点后，可在设置中点击「我已手动补满 PP」重置计数及断点。

## 提醒与保护

保留原始区域、0.8逃跑图像门槛及两次独立截图的闪光检查。点击前 OCR 偶发漏读时，仅在新的逃跑图像仍匹配的情况下使用本轮已确认按钮位置；图像不匹配仍停止。甜甜香气初次和重试均使用5，PP瞬移使用4。

仅闪光和验证码允许远程喵提醒。异常与测试仅本地提示，不打电话。喵码保存在本机 notification.json；不要公开此文件。发行 ZIP 使用空白提醒配置。

游戏失焦、位置变化、验证码、闪光、识别错误或超时会停止，不能把离线测试当成真实闪光识别保证。

## 验证范围

原生应用编译、页面交互、Python 离线回归及后台连接/退出协议分别验证。游戏内点击命中、PP整条路线、真实闪光识别和手机送达仍需实机验收。测试不会自动开启游戏任务或发送远程通知。

## 工程

Native/ShinyHunt.swift 为 SwiftUI 界面；native_bridge.py 为本地进程连接；app.py 保留原引擎与旧界面代码；mac_backend.py 保持原生截图、OCR和输入适配。修改 Swift 后执行 build_native.sh 重新编译；Apple Silicon macOS 14+ 为当前构建目标。只交付固定名称的当前工程与 Mac_Shiny_Hunt_Backup.zip 一份备份。
